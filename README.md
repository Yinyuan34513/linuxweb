# linuxweb — a hyper-realistic Linux 7.2.8 boot console

A dependency-free web page that renders an x86_64 Linux 7.2.8 boot / kernel log
on a `<canvas>` using the **authentic Linux VGA 8x16 bitmap font**, pixel for
pixel, in an 80x25 text grid.

It is not Linux. It just looks like it.

## What is real

- **The font.** Taken from the Linux 7.2.8 source itself:
  `lib/fonts/font_8x16.c` (there is no `font8x16.h` in 7.2.8). 4096 bytes =
  256 glyphs x 16 rows, one byte per row, MSB = leftmost pixel — the classic VGA
  8x16 font generated by `cpi2fnt`.
- **Every log line.** Each line is anchored to a real `printk`/`pr_*` format
  string in the 7.2.8 tree. `tools/registry.json` names the source `file` and a
  `match` substring for each ordered line; `tools/build_bootlog.py` asserts that
  anchor still exists and fails loudly if it ever drifts.

## What "complete kernel log" means here

A literally complete dmesg is impossible — it depends on the machine, the build
config and the hardware. This project defines it as **complete phase coverage**:
one ordered, traceable transcript from the decompressor through the init
handoff, where every line is backed by a real 7.2.8 format string. The values
(CPU count, memory map, device names) are plausible renders of those formats.

The `init`/systemd phase is **not** in the kernel tree, so it cannot be mined
from Linux; it lives in the clearly separated, hand-written `data/userland.txt`
and is appended verbatim.

## `file` is the real libmagic

`file` is not a guess here. `assets/libmagic.js` is **file(1)'s own library**
(`src/apprentice.c`, `softmagic.c`, `ascmagic.c`, `readelf.c`, `is_json.c`,
`is_tar.c`, …) compiled to WebAssembly with Emscripten, and the database is the
**system's** `/usr/share/misc/magic.mgc` — the same bytes the machine's `file`
uses. So `file` here runs the same code paths, over the same rules:

```sh
file /etc/hostname     # /etc/hostname: ASCII text
file /boot/vmlinuz-7.2.8
file -I /tmp/x.json    # mime type only
file -b /dev/sda       # brief, no name column
```

Details that only come out right if it is the real thing:

- the name column is padded to the widest operand, with `-F` as the separator;
- a file that cannot be opened is reported as
  ``file: cannot open `x' (No such file or directory)`` **and file still exits 0**;
- a symlink is reported as a symlink unless `-L` is given;
- an ELF gets the full description — `pie executable, dynamically linked,
  interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=…, for GNU/Linux 3.2.0,
  stripped` — which `readelf.c` gets by `pread()`-ing the program headers and
  PT_NOTE sections. That is why `src/magic.js` hands libmagic a file rather than
  a buffer.

### It is verified against the real `file`, not assumed

`tools/verify_magic.js` runs the same buffers through both: the wasm build with
the embedded database, and the system's `file -b -m` with the same one.

```console
$ node tools/verify_magic.js
416 identical, 0 different, 416 files
```

416 files — every ELF in `/bin`, configs, docs, images, archives, plus synthetic
samples (JSON, CSV, gzip, zip, PNG, PDF, tar, wasm, UTF-8, random) — and not one
byte of difference.

### Rebuilding it

The database is 8.1 MB, which is why `src/magicmgc.data.js` carries it gzipped
(383 KB) and `src/magic.js` inflates it with `DecompressionStream` before
loading it.

```sh
git -C ../file fetch --depth 1 origin tag FILE5_45        # the mgc's version
git -C ../file worktree add ../file545 FILE5_45
. ~/gnos/emsdk/emsdk_env.sh
sh tools/build_libmagic.sh ../file545                     # -> assets/libmagic.js
node tools/gen_magicmgc.js assets/libmagic.js /usr/share/misc/magic.mgc \
     src/magicmgc.data.js
node tools/verify_magic.js && node tools/test_magic.js
```

The library has to be the same release as the database — `magic_load()` reads
the records as `struct magic`, and the struct grew in 5.46, so a 5.48 library
rejects a 5.45 `magic.mgc` outright. Two `#define`s in `tools/build_libmagic.sh`
matter for correctness, not just for compiling: `BUILTIN_ELF` (without it
`readelf.c` compiles to a stub and every ELF is "shared object") and `ELFCORE`
(where the note-parsing flag bookkeeping lives).

To compile a database instead of embedding the system's — for instance a much
smaller page — pass either our curated `data/magic` or the complete Magdir:

```sh
node tools/gen_magicmgc.js assets/libmagic.js data/magic src/magicmgc.data.js
node tools/gen_magicmgc.js assets/libmagic.js ../file545 src/magicmgc.data.js all
```

A compiled database has to be produced *by the library that reads it* (the
format is versioned and `magic_load()` rejects a mismatch), which is why that
step runs the wasm module under node and calls `magic_compile()` inside it
rather than shelling out to the system `file`.

## Login

The console ends at a real getty. Credentials (from `/etc/shadow`, verified with
SHA-256):

| user | password |
|---|---|
| `linuxweb` | `linuxweb` |
| `root` | `root` |

`daemon`, `bin`, `sys` and `sync` are locked (`*`), as on a real machine.

getty prints `/etc/issue`, reads the username (echoed, editable) and then the
password (never echoed), and on failure prints `Login incorrect` and re-prompts
after a short back-off — a retry behaves exactly like the first attempt. Success
prints `Last login:` plus `/etc/motd` and starts a login shell; when the shell
exits you are dropped back to `login:`, like a console.

The `Last login:` line is **generated at login time**, not baked in: it formats
the *previous* session's time and tty, which are kept in `/var/log/lastlogin`
(so they survive a reload like any other file), and falls back to the boot time
when there is no record yet. The fields are read as UTC, because the machine is
set up in UTC -- `/etc/localtime`, the kernel banner and the boot log all say so
-- so the line agrees with them whatever timezone the browser runs in.

## The shell

A bash-style shell — **not** GNU bash. It covers quoting, `$var` / `${var}` /
`$(...)` / `$((...))` / backticks, `$'...'` ANSI-C quoting, globbing, pipelines,
`> >> <`, `2>&1`, `; && ||`, `if`/`for`/`while`, single-line function definitions
with `$1..$9` / `$#` / `$@`, aliases, history, tab completion and readline-style
line editing, over coreutils backed by the VFS.

Builtins: `cd pwd export unset set alias unalias source . exit return read
history help type command eval umask jobs wait test [ kill shift let exec trap
hash bg fg suspend times local declare typeset readonly shopt ulimit clear reset
logout sync bind` plus `echo printf true false`.

- **`help`** is bash's, text and all. `tools/gen_bash_help.py` extracts every
  builtin's `$SHORT_DOC` / `$LONG_DOC` straight out of bash 5.3's
  `builtins/*.def`, so `help NAME` prints `<name>: <usage>` followed by the doc
  indented four spaces (blank lines included), `-s` gives the usage line, `-d`
  gives `<name> - <description>`, and `-m` the NAME/SYNOPSIS/DESCRIPTION
  manpage form. The bare listing splits the terminal in half (colwidth =
  `cols / 2`, truncated with `>`), and an unknown topic prints bash 5.3's exact
  `no help topics match \`X'.  Try \`help help' or \`man -k X' or \`info X'.`
  on stderr. Of the 48 builtins we ship, 33 produce byte-identical output to the
  host's bash 5.2.21; the other 15 differ only where 5.3 changed the wording.
- **`bind -P`** prints the real readline key table, captured verbatim from bash
  (173 lines, `abort can be found on "\C-g", "\C-x\C-g", "\M-\C-g".` and
  friends). Bare `bind` still prints the table of chords this editor actually
  implements.
- **`set -o` / `set +o`** print the real option list with an interactive shell's
  values (`emacs`, `history`, `histexpand` and `monitor` on), in bash's
  `%-15s\t%s` layout.
- **Errors** carry bash's wording and exit statuses: `bash: X: command not
  found` (127), `... No such file or directory` (127), `... Is a directory`
  (126), `... Permission denied` (126). `2>&1` really merges the streams.
- **command not found** follows bash's failure modes: `bash: NAME: command not
  found` (127), `... No such file or directory` (127), and `... Is a directory` /
  `... Permission denied` (126) for path-shaped words. `command_not_found_handle`
  is honoured; the built-in one is the Debian handler that prints
  `Command 'X' not found, but can be installed with: sudo apt install X`.
- **`bind`** prints the complete Ctrl+ table below.

## GNU coreutils

The commands are not shallow imitations. Each one is written against what GNU
coreutils 9.4 actually prints, and `tools/difftest.js` runs a command line
through **both** the real `/bin/sh` and this shell and compares stdout, stderr
and exit status -- 177 cases, all matching:

    node tools/difftest.js              # every group
    node tools/difftest.js wc sort sed  # just these

Things that had to be measured rather than guessed:

- **`wc`** has two layouts. `cat f | wc` pads every count to seven columns;
  with operands the numbers share one width, taken from the largest *byte*
  count (which is why `wc -w f1 big` comes out three wide even though its word
  counts are one digit); a lone standard input is not padded at all. `wc -L`
  totals a maximum, everything else a sum.
- **`cksum`** is not IEEE CRC-32. GNU builds its table from a `GEN` polynomial
  and then folds the file's *length* in before complementing it, so
  `printf abc | cksum` is 1219131554 where zlib says 891568578.
- **`comm`** indents by printed column position, so `-1` and `-2` move the
  remaining columns left instead of leaving a gap.
- **`od`**'s default format is a little-endian octal word, and a lone trailing
  byte still fills six columns (`000147`).
- **`sort -k`** names a *span* between two field offsets, not one field, and
  falls back to the whole line unless `-s`.
- **`seq -w`** takes no argument: `seq -w 8 10` prints 08 09 10.
- **`fmt`** pulls words back rather than leave a stub last line.
- **`head -3`** is `head -n 3`, and **`od -w 2`** is a file called `2`.
- **`printf`** reuses its format for each argument, with flags, width and
  precision, and does *not* expand escapes in a `%s` argument (that is `%b`).
- **`sed`** is a real stream editor: line addresses (`N`, `N,M`, `$`, `/re/`,
  `first~step`, `N+N`, and ranges that open and close across lines), `!`,
  `s///` with `g`/`i`/`p`/`q`, `y///`, `p d q Q = a i c n N P h H g G x b t T`,
  `{ }`, labels, `-e` more than once, POSIX classes such as `[[:alpha:]]`, and
  BRE translated to a RegExp -- in which `\(` is a group and a bare `(` is an
  ordinary character, as in grep.

`src/coreutils_help.js` is generated from the real binaries'
`--help`/`--version` output for 102 programs, so `ls --help` prints what `ls`
prints, down to the `Try 'ls --help' for more information.` line that every
usage error ends with.

## systemd

`systemctl`, `journalctl` and `dmesg` are front ends over one model in
`src/systemd.js`, so the unit states, the journal and the kernel log cannot
tell three different stories. The journal begins as the boot: every line the
console stamped becomes an entry with both a monotonic and a wall-clock time,
and the unit events systemd would have written are woven in where they belong,
so `journalctl -b` reads in order.

- **`systemctl`** answers `status`, `list-units`, `list-unit-files`,
  `is-active`, `is-enabled`, `is-failed`, `start`, `stop`, `restart`, `reload`,
  `enable`, `disable`, `cat`, `show`, `daemon-reload`, `list-jobs` and
  `get-default` in systemd's layout -- the coloured state marker, the `Loaded:`
  and `Active:` lines, `Main PID`, the CGroup and process tree, the unit's
  newest log lines -- and its exit codes (0 active, 3 not active, 4 for a unit
  it has never heard of). The unit files are real files, so `systemctl cat ssh`
  and `cat /lib/systemd/system/ssh.service` show the same text.
- **`journalctl`** handles `-n -u -k -p -o -r -b -S -U --disk-usage
  --list-boots`, prints the short format
  `<when> <host> <ident>[<pid>]: <message>`, and closes with the hints a
  non-terminal reader gets.
- **`dmesg`** reads the ring buffer the console printed (`/var/log/dmesg`) with
  the util-linux option set: `-H` for the wall clock and the offset since the
  previous line, `-T`, `-t`, `-r`, `-c`, `-C`, `-l`, `-f`, `-F`, `-n`, `--`.

There is no systemd on the machine this runs on, so `tools/test_systemd.js`
checks these against the published formats and against each other (79 checks:
the state that `systemctl` reports, the entries `journalctl` prints, and the
kernel lines `dmesg` shows all agree).

## Virtual terminals (emuvt)

The console is a real VT emulator, not just an SGR filter. `src/vt.js` implements
the escape set a Linux virtual terminal understands:

- **cursor**: `CUP/HVP`, `CUU/CUD/CUF/CUB`, `CNL/CPL`, `CHA/VPA`, `HPR`, save and
  restore (`DECSC/DECRC`, `CSI s`/`CSI u`), with origin mode and the wrap
  behaviour a real VT has (writing the last column leaves a *pending* wrap).
- **erase/edit**: `ED 0/1/2/3`, `EL 0/1/2`, `IL`, `DL`, `ICH`, `DCH`, `ECH`.
- **scrolling**: `DECSTBM` scroll margins, `SU`, `SD`, `IND`, `RI`, `NEL`.
- **tabs**: default stops every 8 columns, `HTS`, `TBC 0/3`, `CHT`, `CBT`.
- **modes**: `DECAWM` (?7), `DECOM` (?6), `DECTCEM` (?25), `DECCKM` (?1), `IRM`,
  and the alternate screen (?47 / ?1047 / ?1049).
- **queries**: `DSR 5/6` and `DA1` reply through `term.onResponse`.
- **reset**: `RIS` (`ESC c`), which also clears the margins and tab stops.
- `OSC` / `DCS` / `PM` / `APC` strings and charset designations are consumed.

On top of that, **six virtual terminals** share the canvas. `Ctrl+Alt+F1..F6`
switches (as does the `chvt N` command); each VT keeps its own cell buffer,
cursor, modes and its own getty/shell session, and only the foreground VT paints
and blinks. `tty` and `fgconsole` report the active VT.

## Devices (devtmpfs)

`/dev` is not a directory of static files — it is generated from a device
registry, the way the kernel's devtmpfs works. A device node knows its type and
major/minor, so `ls -l /dev/null` prints `crw-rw-rw- 1 root root 1, 3`, and the
same registry feeds `/sys/dev/char/<maj>:<min>`, `/sys/dev/block/<maj>:<min>`,
`/proc/devices`, `/proc/partitions`, `lsblk`, `stat` and `udevadm info`.

```sh
ls -l /dev              # device nodes with real major/minor
cat /proc/devices       # grouped by driver class
ls /sys/dev/char        # 1:3 5:0 4:1 ...
stat /dev/sda
hotplug sdb             # a device appears in /dev + /proc/partitions
hotplug --remove sdb
mknod mydev c 10 99     # create your own node
udevadm info -n /dev/sda
```

The mount is read-only (like a real devtmpfs) and is never written to IndexedDB:
dynamic subtrees are skipped by the persistence layer entirely. It is re-mounted
automatically after every open and after `?fs=reset`.

## Packages (apt)

`apt` is an emulated Debian package manager whose packages install **working**
commands. Installed state lives in `/var/lib/dpkg/status` (dpkg's own format), so
it survives a reload, and each package's commands are re-bound to their
implementations at boot.

```sh
apt update
apt search cow
apt list
apt show cowsay
sudo apt install cowsay          # progress, then the command works
cowsay hello
dpkg -l
apt remove cowsay
```

| package | installs | notes |
|---|---|---|
| `cowsay` | `cowsay` | talking cow, `-e` eyes, `-l` list |
| `fortune-mod` | `fortune` | cookie of the day |
| `figlet` | `figlet` | big ASCII banners |
| `neofetch` | `neofetch` | logo + system facts (counts installed packages) |
| `sl` | `sl` | animated train — uses cursor addressing |
| `cmatrix` | `cmatrix` | matrix rain, `Ctrl+C` to stop |
| `htop` | `htop` | full-screen snapshot on the alternate screen |
| `curl` | `curl` | fake fetch with a progress line |
| `git` | `git` | `--version`, `init`, `status` |
| `hello` | `hello` | GNU hello |

Because bash's `command_not_found_handle` is the Debian one, the loop closes:
type a command you have not installed, and it tells you to `sudo apt install` it.

### The wording is copied, not invented

The apt/dpkg text is transcribed from the real tools rather than written by hand,
which is where the details come from: the `This APT has Super Cow Powers.` sign-off
in `apt --help`, the `Suggested packages:` block, `Installed-Size: 7339 kB` with
its space and unit, the `Get:` / `Ign:` / `Err:` update blocks with their
`404  Not found [IP: ...]` continuation, and `dpkg -l`'s fixed column geometry
(name@4 w50, version@54 w41, arch@95 w13, description w151 — a 119-character
header and a 259-character rule, unchanged even on an 80-column console, which is
why `dpkg -l` wraps). Captured read-only with `apt list/search/show/install -s`,
`dpkg -l`, and `apt-get update` redirected to `/tmp`; tty-only behaviour was
checked under `script -qc 'stty cols 80; ...'`.

## Ctrl+ keys

The line editor implements readline's emacs mode. Every chord is bound; the full
33-entry table (`a`–`z` plus `@ [ \ ] ^ _ ?`) lives in `src/bash.js` as `CTRL`
and is printable with the `bind` builtin.

| key | action | key | action |
|---|---|---|---|
| `C-a` / `C-e` | start / end of line | `C-k` | kill to end of line |
| `C-b` / `C-f` | back / forward one char | `C-u` | kill to start of line |
| `C-c` | abort the line | `C-w` | kill the word behind |
| `C-d` | delete char, or exit on empty | `C-y` | yank the killed text |
| `C-h` / `C-?` | delete the char behind | `C-t` | transpose characters |
| `C-i` | complete (same as Tab) | `C-_` | undo |
| `C-j` / `C-m` | accept the line | `C-v` | insert the next char literally |
| `C-l` | clear the screen | `C-r` / `C-s` | reverse / forward history search |
| `C-n` / `C-p` | next / previous history | `C-g`, `C-\`, `C-[` | abort |
| `C-o` | accept and fetch the next | `C-z` | suspend (no job control here) |
| `C-@` | set the mark | `C-q`, `C-x`, `C-]`, `C-^` | unbound |

getty has its own complete table: cursor movement, `C-c` / `C-d` / `C-g` / `C-\`
/ `C-[` restart or abort the login, `C-h` / `C-?` / `C-u` / `C-w` edit the
username, and every other chord is consumed rather than inserted.

## Filesystem (IDBFS)

`src/vfs.js` is an IndexedDB-backed POSIX-ish tree: one record per path, a
write-behind queue flushed in a single transaction, and an explicit
`syncfs(populate, callback)` that flushes and optionally reloads the tree.
Generated nodes such as `/proc/*` are computed and never persisted; everything
else — including a `mkdir -p` tree you make yourself — survives a reload.

- `?fs=reset` drops the store and reseeds the default Debian-ish tree.
- `idbfs` prints mount status, record/file/dir counts, bytes and queued writes;
  `idbfs --sync` flushes, `idbfs --sync --populate` flushes and reloads.
- `sync` flushes immediately.

Chrome blocks IndexedDB on `file://`, so persistence needs HTTP
(`python3 -m http.server`); without it the page still works, just in memory-only
mode.

`gen_bash_strings.py` anchors every banner string to bash-5.3's own source.

## Timing

Timestamps are **not** baked into the log. Real klog timestamps depend on how
long the machine actually took, so `build_bootlog.py` emits only a planned delay
per line and `main.js` stamps each line with the **measured elapsed time** as it
replays — the numbers you see are how long this boot really took.

Tune it in the URL:

- `?instant=1` — print the whole log immediately (no waiting).
- `?minDelay=..` — ms between ordinary lines (default `24`).
- `?timeScale=..` — ms per second of planned boot time (default `1800`).
- `?shell=0` — stop after the log, do not start getty.
- `?vt=N` — boot straight into virtual terminal N (1-6).

Click or press a key to fast-forward the boot.

## ANSI colour

The renderer is an ANSI terminal: it handles SGR (`ESC [ ... m`) with `;` or `:`
separators, indexed colours `30-37 / 90-97 / 40-47 / 100-107`, the complete
256-colour forms `38;5;n` / `48;5;n` and `38:5:n`, truecolour `38;2;r;g;b`
(including the optional `38:2::r:g:b` colourspace slot), and the attributes
`0 1 2 4 7 8 9` with their resets — bold brightens indexed 0-7, dim darkens
8-15, `7` swaps fg/bg, `8` paints fg as bg, `4` and `9` draw underline and
strikethrough. The 256-colour cube and the 24-step grey ramp are exact.

Bash's escape forms all produce real ESC bytes, so colours actually render
instead of appearing as literal text:

```sh
printf '\033[31mred\033[0m\n'                 # printf expands escapes in the format
echo -e "\e[1;32mgreen\e[0m"                  # echo -e expands \e, \033, \x1b, ...
printf '%s\n' $'\033[38;5;196mcube\033[0m'    # $'...' ANSI-C quoting
```

`expandEscapes()` covers `\a \b \e \E \f \n \r \t \v \\ \' \" \? \c`, octal
`\0nnn`, hex `\xHH` and Unicode `\uHHHH` / `\UHHHHHHHH`; `%b` in `printf` expands
its argument the same way. The prompt decoder expands `\033` / `\x1b` too, which
is what makes Debian's coloured `PS1` work.

The userspace colours are systemd's own, taken from `src/basic/ansi-color.h` and
`src/core/job.c`:

| element | sequence | systemd constant |
|---|---|---|
| `[  OK  ]` | `ESC[0;1;32m` … `ESC[0m` | `ANSI_HIGHLIGHT_GREEN` / `ANSI_NORMAL` |
| bold heading | `ESC[0;1;39m` … `ESC[0m` | `ANSI_HIGHLIGHT` |
| warning tag | `ESC[0;1;38:5;185m` | `ANSI_HIGHLIGHT_YELLOW` = khaki3 |
| grey | `ESC[0;38;5;245m` | `ANSI_GREY` |

systemd's tag text is `"  OK  "` (from the `job_done_messages[]` table) wrapped
in `[` `]`, so the tag is exactly `[  OK  ]`.

### Palette

`?palette=xterm` (default) renders the base 16 colours from the modern-terminal
xterm-256 palette — default fg `#e5e5e5`, bold green `#00ff00` — i.e. what
systemd's `ESC[0;1;32m` looks like in a modern terminal today.

`?palette=vga` renders them from the Linux console / vgacon palette — `#aaaaaa`
on black, bold green `#55ff55` — i.e. what systemd's *fallback* constants render
on a real VT (vgacon has only 16 colours, so systemd falls back to
`ANSI_HIGHLIGHT_YELLOW_FALLBACK` / `ANSI_BRIGHT_BLACK` there).

Note on authenticity: the kernel's own `printk` output is **monochrome** on the
vgacon console (Linux does not colour kernel messages by severity), so the
kernel portion of the log stays default light grey; the colour lives in the
userspace/init phase. And because a healthy boot succeeds at every job, every
tag in this transcript is `[  OK  ]` — systemd's yellow (`[DEPEND]`, `[ASSERT]`,
`[UNSUPP]`) and red (`[FAILED]`, `[ TIME ]`, `[ ONCE ]`, `[FROZEN]`) tags only
appear when something goes wrong, and grey is for debug-level output.

Any line — kernel or not — can carry colour: put an `\e[...]m` marker in a
registry `text` or in `data/userland.txt` (`\e` is expanded to a real ESC byte
by `build_bootlog.py`).

## Run

Open it directly — everything is inlined, so `file://` works (IndexedDB excepted):

```sh
xdg-open index.html
```

Or serve it (needed for a persistent filesystem):

```sh
python3 -m http.server 8000    # http://localhost:8000
```

## Async commands

A command may return `{async: true, start(io)}` and take over the screen until it
calls `io.done(code)`, writing through `io.write`. That is what drives `sl`,
`cmatrix`, `htop` and apt's download progress; `Ctrl+C` aborts the task.

## Notes / boundaries

- Only CP437 codes 0..255 are drawable (`charCodeAt(i) & 0xff`); the log is
  ASCII.
- Only the 8x16 glyph is used. The hardware 9th "line graphics" column that
  `vgacon` can generate is a CRTC-side feature and intentionally out of scope.
- Font data is derived from GPL-2.0 Linux source (`lib/fonts/font_8x16.c`); the
  banner strings come from GPL-3.0 bash 5.3; `assets/libmagic.js` is
  BSD-licensed file(1) 5.48.
- No job control (`C-z`, `bg`, `fg`, `wait` are accepted but inert), no job
  pipelines across processes, and no multi-line `if`/`for`/`while` bodies — the
  shell is a single-page simulator, not a process-based shell.
- `cat` with no operands on a terminal is an interactive reader: keystrokes are
  captured and copied back through cat's own filter until `Ctrl+D`. With a pipe
  or a redirect it is an ordinary filter again.
